Core 1 · Inventory

What the public Points Registry gives you

The official record of WSDC Jack & Jill results at Registry Events. From outside, that mostly means point-bearing competitor histories.

Available

  • Dancers with a WSDC Competitor ID and awarded points
  • Event editions and scored results by contest
  • Tier as a size band for division×role (range, not exact headcount)
  • Registry event calendar/list (separate from who stepped on the floor)

Not in the open layer

  • A full contest starting list in analytics-ready form
  • Dancers who competed but never earned a point
  • Clean geography without name/location cleanup

Registry definition: WSDC Registry Event Rules 2026.1B, Overview / Points Registry.

Core 1 · Inventory

What the rules already require you to submit

Under §2.3 Competitor Results Reporting, members report all WSDC J&J results. The live vehicle is the Score Report workbook (v2026.1B): it already asks for more than the public lookup shows.

  • All petitions
  • Finalists’ WSDC IDs (when an ID has been assigned)
  • Competitor counts per division (for Tier)
  • List of all competitors registered — Score Report sheet Competitors List
  • Plus sheet Dual / Multiple Roles for people who danced more than one role

The question is not “should we collect lists?”

The sheets already exist. Open questions: required columns (is WSDC ID mandatory on every row, including people with no points yet?), machine-readable format, and whether submitted xlsx files stay with event protocols or land in a working database that can join the Points Registry.

Registry Event Rules 2026.1B §2.3 (items 1-4); Score Report Form v2026.1B on WSDC Forms. Results due no later than three days after the event closes.

Core Frame

Three populations. Do not mix them in one report

Board questions mix these layers unless we name which one we mean.

Community (broad)

People outside scored outcomes and possibly outside registry events.

Source: separate methodology — not the Points Registry alone

Entry population

Everyone registered in WSDC J&J. Already collected in Score Report lists.

Source: Competitors List / Dual Roles — needs schema + retention

Scored population (public)

Unique WSDC IDs with points. What the open Points Registry shows.

Source: public lookup / scored history

Four directions from the committee ask

  2. Points & tiers: current structure; impact of changes; progression for the majority
  3. Event landscape & capacity: where growth is justified (local organizer + territory case); when to limit new events

Core Bridge

From agenda to four gaps

Without shared definitions of “dancer,” “entrant,” “region,” and “event,” board reports will argue with each other.

A. Identity

An ID appears after the first point. Before that, the person is not a registry entity.

B. Coverage

Public layer = scored history. Full lists sit in Score Report — format and retention unclear.

C. Data quality

Free-text intake on Event Update / New Event Application / Score Report multiplies name and location drift.

D. Geo / landscape

Capacity needs a local organizer and territory case; analytics only confirms demand.

Core Gap A · Identity

IDs only after a point — and what that means

The rules assign a Competitor ID only after the dancer receives a point. Before that, the person is invisible in the public Points Registry.

Hits the agenda

  • Counts: undercounts actives, especially Newcomer and Novice
  • Progression: entry funnel cut off at people who already scored
  • Capacity: novice demand barely shows in the registry

Process moves

  • Keep “ID after points” or change it — either way, label reports honestly
  • If after points: write scored population, not “whole community”
  • Full population work needs Score Report lists once schema and retention are clear

Core Gap B · Coverage

Lists are collected — not yet a working analytics layer

Score Report already has Competitors List and Dual / Multiple Roles. The public registry still shows mostly people who scored. The open questions are format, ID handling, and where files go after submit.

Why it matters

  • Counts: registry skill counts = scored, not starters
  • Progression: cannot separate “dances little” from “never reaches points”
  • Capacity / point structure: fragile without the entry funnel

What to lock

  • Sheet schema: required fields; how WSDC ID is entered when the dancer has none yet
  • Path after submit: xlsx with protocols only, or a store that can join the Points Registry?
  • If only files today — design that working store
Core Gap C · Data quality

Entity quality: what shows up in open data

Name and location mismatches are the downstream effect of free-text intake on existing WSDC forms — not malice.

1. Multiple titles for one series
Asia WCS Open XI, XIII, 10th Anniversary → canonical Asia WCS Open. Without aliases, time series break.
2. Empty location
Scandinavian Open: empty location on all 993 local result rows.
3. Brand spelling variants
St.Petersburg / Saint Petersburg WCS Nights; Vestigala / Westie Gala.
4. Same label, different histories
Spring Swing: Stockholm and Detroit. Sunny Side Dance Camp: Crimea, then Torrevieja.

Intake: Event Update, New Event Application, and Score Report Info Summary take event name and location as free text. Blank retype → new aliases and geo spellings.

Same fields, different writing. Small sample from open data.

Core Gap C · Fix

Directories + forms that enforce them

Without master data, event and country series break, editions double-count or vanish, and automation copies the mess. Fix the existing forms — do not invent parallel paperwork.

Directories

  • Event directory: one canonical name / one ID
  • Location directory: city + country (US → state too)
  • Change types in advance: new event, rename, location move, correction
  • Organizers own the accuracy of their rows

How forms enforce it

  • Event Update: pick existing event → prefill; no blank retype of name/location
  • New Event Application: after approval → new directory row
  • Score Report: Event Name / Location from directory or Event ID
  • Free text OK: contacts, venue ops, ownership, shuttle
Core Gap D · Landscape

Landscape and capacity: organizers first

WSDC does not run events. A blank spot on the map is not enough — there must be a local organizer who carries the risk, plus a credible territory case.

Organizer in the process

  • Named organizer takes operational and financial responsibility
  • Structure the case already asked on New Event Application (viability + grid review)
  • Crowded region vs one large event and a growing scene — different decisions

Where analytics fits

  • Confirms demand signals: nearby entry load, density, scored activity
  • Does not replace the organizer’s plan or guarantee ROI
  • Keep free text off name/location; separate metrics: supply, scored demand, entry demand
Core Summary

Matrix: what public data can answer today

Board question Today (public registry) What unlocks a fuller answer
Competitors by skill 2021-2026 (+ region) Partial unique IDs with points; region weak / via event proxy Retain/join Score Report lists + ID policy + clean geo
Points/tiers & progression majority Partial point distribution and scored transitions; entry funnel truncated Entries + an explicit “majority” definition

Point structure change analysis Partial simulations on scored history; limited without the full funnel Agreed KPIs/scenarios + entries for sensitivity

On the public registry alone, none of these are fully closed.

Core Close

What to put in order — and three questions

Checklist

  1. Score Report lists: schema (incl. WSDC ID when none yet) + where files go after submit
  2. ID rule: keep “only after a point” or change; label metrics accordingly
  3. Directories + forms: Event Update prefills; stop free-text name/location
  4. Metric dictionary: scored vs entry vs community
  5. Trial / new events: structure New Event Application case vs event grid

Ask on the call

  1. After Score Report submit: xlsx with protocols only, or a central store?
  2. For 2021-2026, are Competitors List / Dual Roles still recoverable?
  3. Who owns Event Update / New Event Application / Score Report intake — and who can change it?

Close: public data already supports careful analysis. Durable board answers need Score Report lists as a working layer and Event Update without free-text name/location drift. Tooling stays the committee’s choice.

Appendix Q1

Competitors by skill / region

Possible now

  • Unique IDs with points by year
  • Cuts by scored division
  • Rough geo via event location (proxy)

Not honestly “community”

  • Entrants without points
  • True dancer home region
  • Newcomer funnel before first point
Appendix Q2

Points, tiers, progression majority

  • Can: point concentration, progression speed, scored transitions; before/after rule changes
  • Careful: define “majority” (all IDs? active in a year? ≥N points?)
  • Need: entry data to separate “no points” from “did not enter”
Appendix Q3

Event landscape & capacity

  • Process first: local organizer + short case for the territory; WSDC validates motivation, does not organize
  • Can: registry event counts, geography, 2021-2026 dynamics, regional entry load (when lists exist)
  • Partial: confirm demand via scored travel, event density, registrations at nearby events
  • Cannot decide alone: whether an event will pay off for the organizer
Appendix Q4

Point structure change

  • Can: scenario recalculation on scored history; sensitivity of tops and thresholds
  • Risk: optimizing for people already in the registry without an entry model
  • First KPIs: majority growth, threshold fairness, organizer load
Appendix Tiers

Tier is a size band, not an exact count

In the rules, Tier depends on unique competitors in a division×role. Public data can sum those range bounds. That is order of magnitude, not headcount.

  • Useful for comparing event scale
  • Does not replace the named entry list from §2.3
  • Open-ended upper tiers need an uncertainty note
