Points Registry and board analytics:
what the public layer shows, and what it misses

A plain look at what the open registry can support, where the rules already ask for more than the public lookup shows, and which process fixes unlock the committee’s questions.

Core 1 · Inventory

What the public Points Registry gives you

The official record of WSDC Jack & Jill results at Registry Events. From outside, that mostly means point-bearing competitor histories.

Available

  • Dancers with a WSDC Competitor ID and awarded points
  • Event editions and scored results by contest
  • Tier as a size band for division×role (range, not exact headcount)
  • Registry event calendar/list (separate from who stepped on the floor)

Not in the open layer

  • A full contest starting list in analytics-ready form
  • Dancers who competed but never earned a point
  • Clean geography without name/location cleanup

Registry definition: WSDC Registry Event Rules 2026.1B, Overview / Points Registry.

Core 1 · Inventory

What the rules already require you to submit

Under §2.3 Competitor Results Reporting, members report all WSDC J&J results. The live vehicle is the Score Report workbook (v2026.1B): it already asks for more than the public lookup shows.

  • All petitions
  • Finalists’ WSDC IDs (when an ID has been assigned)
  • Competitor counts per division (for Tier)
  • List of all competitors registered — Score Report sheet Competitors List
  • Plus sheet Dual / Multiple Roles for people who danced more than one role

The question is not “should we collect lists?”

The sheets already exist. Open questions: required columns (is WSDC ID mandatory on every row, including people with no points yet?), machine-readable format, and whether submitted xlsx files stay with event protocols or land in a working database that can join the Points Registry.

Registry Event Rules 2026.1B §2.3 (items 1-4); Score Report Form v2026.1B on WSDC Forms. Results due no later than three days after the event closes.

Core 2 · Board agenda

Four directions from the committee ask

  1. Competitor base 2021-2026: counts by skill level; overall community; region if possible
  2. Points & tiers: current structure; impact of changes; progression for the majority (many points earned by a small minority)
  3. Event landscape & capacity: where growth is justified (local organizer + territory case); when to limit new events; analytics confirms demand signals
  4. Point structure: how to test with data whether the structure should change

Next slides are not numbers. They map what blocks a straight answer and what process work unlocks one.

Core Bridge

From agenda to four gaps

Without shared definitions of “dancer,” “entrant,” “region,” and “event,” board reports will argue with each other. The open registry has four structural holes.

A. Identity

An ID appears after the first point. Before that, the person is not a registry entity.

B. Coverage

Public layer = scored history. Full lists already sit in Score Report sheets — format and retention unclear.

C. Data quality

Free-text intake on Event Update / New Event Application / Score Report: name variants, empty locations, drifting series.

D. Geo / landscape

Capacity is not a map exercise: local organizers, territory case, then analytics to confirm demand.

Core Gap A · Identity

IDs are assigned only after a point

This is not an inference from the scrape. The rules say a Competitor ID is assigned only after the dancer receives a point.

  • Before the first point, the person is not trackable in the Points Registry as an entity
  • Someone can compete repeatedly and still be invisible to public analytics
  • “Dancers in the community” and “unique WSDC IDs with points” are different metrics

Registry Event Rules 2026.1B §3.2.2c; Overview: ID after at least one J&J point.

Core Gap A · Impact

How this hits the agenda

Board questions

  • Q1: undercounts “actives,” especially Newcomer and Novice
  • Q2: the entry funnel is cut off at people who already scored
  • Q3: novice demand barely shows in the registry

Process moves

  • Decide policy: ID only after points (current) or earlier
  • If you keep “after points,” label reports as scored population, not “whole community”
  • For full population work, lean on Score Report Competitors List / Dual Roles (§2.3) — once format and retention are clear
Core Gap B · Coverage

Public registry ≠ full entry list

Outside, we mostly see people who earned points. The full registered list is already collected in the Score Report workbook — sheets Competitors List and Dual / Multiple Roles — but it is not in the open Points Registry.

Visible outside

  • Point rows / ID histories
  • Indirectly: Tier by division×role size

Collected in Score Report, not public

  • Everyone registered in J&J (Competitors List)
  • People who danced dual / multiple roles
  • Exact headcount and share with no points — only if lists are retained and joinable

Tier helps with order of magnitude. It does not replace a named entry list with a clear schema (including how WSDC ID is handled for people who have not scored yet).

Core Gap B · Impact

Impact and path forward

Board questions

  • Q1: skill counts from the registry = scored, not starters
  • Q2: cannot separate “dances little” from “never reaches points”
  • Q3-Q4: capacity and point-structure scenarios stay fragile without the funnel

Process path (Score Report lists)

  • Fix sheet schema: required fields, how WSDC ID is entered when the dancer has no ID yet
  • Trace the path after submit: stay with event protocols as xlsx, or load into a database?
  • If only files today — design a working store so lists can join the Points Registry later
Core Gap C · Data quality

Entity quality: what shows up in open data

Deep work on the registry keeps hitting name and location mismatches. That is the downstream effect of free-text intake on the existing WSDC forms — not malice.

1. Multiple titles for one series
Calendar strings like Asia WCS Open XI, Asia WCS Open XIII, and Asia WCS Open - 10th Anniversary resolve to Asia WCS Open. Without aliases, time series break.
2. Empty location in the results extract
For Scandinavian Open, the local results extract has an empty location on all 993 rows. Geography has to be recovered elsewhere.
3. Brand spelling variants
St.Petersburg WCS Nights / Saint Petersburg WCS Nights; Vestigala / Westie Gala. Without aliases, fake “new” events appear.
4. Same label, different histories
Spring Swing: Stockholm and Detroit. Sunny Side Dance Camp: Crimea, then Torrevieja. You need explicit merge / keep-separate rules.

Where it enters: Event Update and New Event Application take event name and location as free text; Score Report Info Summary does the same for Event Name / Location. Retype from a blank form → new aliases and new geo spellings.

Core Gap C · Locations

Location garbage: why standardization matters

The same fields are written differently. Below is only a small sample from open data; the registry has many more rows like these.

Proposed fix

Central directories for events and locations (canonical name; US locations include state). Then change the existing forms: Event Update selects the event and prefills; New Event Application / Score Report pick location from the directory — free text stays for contacts and venue ops, not for entity fields.

Core Gap C · Impact

Why you cannot “just count” without DQ

What breaks

  • Event and country series
  • Double counts or “missing” editions
  • Regional board conclusions
  • Automation without master data copies the mess

Foundation

  • Event directory: one canonical name / one ID
  • Location directory: city + country in one format (for US events, state too)
  • Organizer forms: Event Update / New Event / Score Report wired to directories
  • Organizers own the accuracy of their rows
Core Gap C · Governance

Directory changes only in advance, under rules

Organizers must keep their event and location rows current. Any change to existing data or creation of a new event is requested ahead of time — then Event Update and Score Report can only select what is already in the directory.

Put change types in the regulations

  • New event (via New Event Application) → new ID + canonical name in the directory
  • Series rename (old name → alias / history)
  • Location change (city/country; US + state)
  • Correction of a directory error

How forms enforce it

  • Event Update: pick existing event → prefill; no blank retype of name/location
  • Score Report: Event Name / Location from directory or Event ID
  • Free text OK: contacts, venue ops, ownership, shuttle notes
  • No directory row → cannot select that event/location in the form

Otherwise free-text variants return (USA / US / United States) and “new” events that are really renames — exactly what blank Event Update / Score Report fields allow today.

Core Gap D · Landscape

Landscape and capacity: organizers first

WSDC does not run events. Organizers request trials and new events, spend money, and carry the risk that an event pays off. A blank spot on the map is not enough — there must be a local organizer and a credible case for that territory.

Organizer in the process

  • Named organizer takes operational and financial responsibility
  • Trial / new event: short territory case (New Event Application already asks viability — keep and structure it)
  • Review against the current event grid (crowded region vs one large event and a growing scene)

Where analytics fits

  • Confirms indirect signals: entry load at nearby events, regional density, scored activity
  • Does not replace the organizer's plan or guarantee ROI
  • Still limited: event city ≠ dancer home; bad geo draws false white space
Core Gap D · Impact

Impact and process path

Risk for Q3-Q4

  • Decisions by map or feel, without a local organizer or territory case
  • Approving another event in an overloaded region without checking motivation
  • Changing point structure without a funnel model

What to lock in

  • Structure New Event Application as the territory case (plus analytics confirmation); keep free text off name/location
  • Stable event geo + entry counts/lists as an analytics layer alongside Tier
  • Three metrics separate: event supply, scored demand, entry demand
Core Summary

Matrix: what public data can answer today

Board question Today (public registry) What unlocks a fuller answer
Competitors by skill 2021-2026 (+ region) Partial unique IDs with points; region weak / via event proxy Retain/join Score Report Competitors List (+ Dual Roles) + ID policy + clean geo
Points/tiers & progression majority Partial point distribution and scored transitions; entry funnel truncated Entries + an explicit “majority” definition
Event landscape & capacity / where needed Partial event map and scored activity; organizer proposals not standardized Organizer justification workflow + entry counts/lists + geo DQ + review vs event grid
Point structure change analysis Partial simulations on scored history; limited without the full funnel Agreed KPIs/scenarios + entries for sensitivity

On the public registry alone, none of these are fully closed. Say that out loud.

Core Close

Checklist: what to put in order

  1. Inventory: where Score Report Competitors List / Dual Roles files go after submit, and for which years they still exist
  2. List schema: required columns; how WSDC ID is handled when the dancer has no ID yet
  3. Retention store: xlsx with protocols only, or a database that can join the Points Registry?
  4. ID rule: keep “only after a point” or change it; how metrics are labeled
  5. Directories + forms: Event Update prefills; New Event Application / Score Report stop free-text on name & location
  6. Board metric dictionary: scored population vs entry population vs community
  7. Trial / new events: structure the case already asked on New Event Application; review against event grid
Core Discovery

Four questions to reconcile

  1. After Score Report submit: do Competitors List / Dual Roles stay as xlsx with event protocols, or load into a central store?
  2. For which years (at least 2021-2026) are those lists still recoverable?
  3. What is required on each list row today — is WSDC ID mandatory when the dancer has no points yet?
  4. Who owns intake process for Event Update / New Event Application / Score Report, and who can change it?

Close: public data already supports careful analysis. Durable board answers arrive when Score Report lists become a working layer and Event Update stops free-text name/location drift. Tooling stays the committee’s choice.

  • First KPIs: majority growth, threshold fairness, organizer load
Appendix Tiers

Tier is a size band, not an exact count

In the rules, Tier depends on unique competitors in a division×role. Public data can sum those range bounds. That is order of magnitude, not headcount.

  • Useful for comparing event scale
  • Does not replace the named entry list from §2.3
  • Open-ended upper tiers need an uncertainty note
Appendix Definitions

Three populations. Do not mix them in one report

Scored population

Unique WSDC IDs with points in the period. What the public Points Registry gives.

Entry population

Everyone registered in WSDC J&J. Already required in §2.3 reporting; needs retention.

Community (broad)

Includes people outside scored outcomes and possibly outside registry events. Separate methodology.

Practice

Label which population each board report uses.
