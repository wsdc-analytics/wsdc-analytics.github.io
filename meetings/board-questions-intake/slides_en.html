Brief Analytics committee · Board intake

How we take Board questions
without expanding the wrong work

A shared way to classify asks by WSDC company data readiness: answerable now (full or partial), data that exists but isn’t in the analytics stream yet, data we believe we can collect inside WSDC, data outside WSDC — and governance that isn’t a dataset.

Scope Why classify

Better current work — not a bigger plate

Board asks arrive mixed. Without a frame, every ask looks like “more analysis,” and the committee drifts into new product fronts while infrastructure and mission work still need support.

Standing rule (Kay)

Use this committee to make current Board initiatives and infrastructure stronger. Default against expanding scope into new hubs, fee experiments, or build-ownership unless the Board mandates it.

What classification does

  • Splits one message into atomic questions
  • Names the data layer each atom needs
  • Separates deliverables from enabling work and from scope decisions
Frame Populations

Three populations. Do not mix them

Community

Broader WCS social and learning world — mostly outside the registry.

Entry

Everyone registered in WSDC J&J. Already requested in Score Report lists (§2.3) — usable analytics need retention and join.

Scored

People with awarded points / Competitor ID after a point. This is what the public registry supports today.

Competitor ID only after a point — Rules 2026.1B §3.2.2c. Aligns with the 1 September analytics brief.

Model Categories

How we sort Board questions

Not “good vs bad database” — how ready WSDC company data is to answer. This is not about a personal analytics store.

C1

Answerable now

Already in a working stream (Points Registry, event catalog). Some asks fully; some only partially (usually Scored) — if that works for the asker.

C2

Data exists in WSDC — not in the analytics stream yet

Already collected (often Google Sheets / Score Report), but not normalized or cleaned, no pipeline. Need company-side prep: schema, aliases, join, retention — to make it usable.

C3

Inside WSDC contour — not collected yet

We believe where to get it inside WSDC. No raw stream yet. First learn to collect → then it becomes C2.

C4

Outside WSDC

Local dances, workshops, non-WSDC weekends, polls. Once collected, those feeds land in C2 (exist, not yet in the shared pipeline).

C5

Separate circle: scope / governance

Priorities, product, policy, fees — not a dataset. Outside the C1–C4 readiness ladder.

C1 · we answer

Full or partial (if accepted). C2/C3 collapse here as enablements land.

C5 · aside

Strategy and ownership — not a rung on this ladder.

Fork: C3 / C4 both feed C2. Then C2 → C1. The question matrix is next: which ask sits where today.

Process Workflow

From ask to track

  1. Intake — asker, text, must-have vs nice-to-have
  2. Decompose — one Board message → several atomic questions
  3. Classify — C1–C5 + population (Community / Entry / Scored)
  4. Respond — deliver (C1), partial + enabling step (C2/C3), collection design (C4), or scope return (C5)
  5. Track & reclassify when an enabling step ships
