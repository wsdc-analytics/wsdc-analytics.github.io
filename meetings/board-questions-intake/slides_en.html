Brief Analytics committee · Board intake

How we take Board questions
without expanding the wrong work

A shared way to classify asks: what we can answer from the public Points Registry now, what unlocks with WSDC source hygiene, what needs new collection, what sits outside the registry — and what is governance, not a dataset.

Scope Why classify

Better current work — not a bigger plate

Board asks arrive mixed. Without a frame, every ask looks like “more analysis,” and the committee drifts into new product fronts while infrastructure and mission work still need support.

Standing rule (Kay)

Use this committee to make current Board initiatives and infrastructure stronger. Default against expanding scope into new hubs, fee experiments, or build-ownership unless the Board mandates it.

What classification does

  • Splits one message into atomic questions
  • Names the data layer each atom needs
  • Separates deliverables from enabling work and from scope decisions
Frame Populations

Three populations. Do not mix them

Community

Broader WCS social and learning world — mostly outside the registry.

Entry

Everyone registered in WSDC J&J. Already requested in Score Report lists (§2.3) — usable analytics need retention and join.

Scored

People with awarded points / Competitor ID after a point. This is what the public registry supports today.

Competitor ID only after a point — Rules 2026.1B §3.2.2c. Aligns with the 1 September analytics brief.

Model Categories

Four data categories + governance

IDNameMeaning
C1Answerable nowPublic / cleaned Points Registry and event catalog
C2After source hygieneRaw WSDC sources exist (e.g. Score Report archive) — need schema, aliases, join
C3Needs WSDC collection designRight place is inside WSDC, but no usable stream yet
C4Outside WSDCLocal dances, workshops, non-registry weekends, polls
C5Governance / scopePriorities, product ownership, policy — not “another extract”

As enablements land, atoms migrate C3 → C2 → C1. C4 stays community-program work. C5 escalates to Board/ops.

Process Workflow

From ask to track

  1. Intake — asker, text, must-have vs nice-to-have
  2. Decompose — one Board message → several atomic questions
  3. Classify — C1–C5 + population (Community / Entry / Scored)
  4. Respond — deliver (C1), partial + enabling step (C2/C3), collection design (C4), or scope return (C5)
  5. Track & reclassify when an enabling step ships
