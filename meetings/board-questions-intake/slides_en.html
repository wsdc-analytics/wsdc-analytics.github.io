Brief Analytics committee · Board intake

From Board questions to WSDC data readiness:
one intake frame

A shared way to classify asks by WSDC company data readiness: answerable now (full or partial), data that exists but isn’t in the analytics stream yet, data we believe we can collect inside WSDC, data outside WSDC — and strategy or product questions that are not a dataset.

Scope Why classify

A shared frame keeps current work strong

Board asks arrive mixed. A shared frame names what each ask needs, so the committee can keep supporting infrastructure and current initiatives.

Committee focus (Kay)

Use this committee to strengthen current Board initiatives and infrastructure. Stay with that focus unless the Board explicitly expands the mandate.

What classification does

  • Splits one message into separate questions
  • Names the data layer each question needs
  • Separates answers we can ship from preparatory work and from mandate decisions
Frame Populations

Three populations. Do not mix them

Community

Broader WCS social and learning world — mostly outside the registry.

Entry

Everyone registered in WSDC J&J. Already requested in Score Report competitor lists — for analytics we need to keep those lists centrally and link them to dancer and event IDs.

Scored

People with awarded points / Competitor ID after a point. This is what the public registry supports today.

Competitor ID only after a point — Rules 2026.1B §3.2.2c. Aligns with the 1 September analytics brief.

Model Categories

How we sort Board questions

Not “good vs bad database” — how ready WSDC company data is to answer.

C1

Answerable now

Already in a working stream (Points Registry, event catalog). Some asks fully; some only partially (usually Scored) — if that works for the asker.

C2

Data exists in WSDC — not in the analytics stream yet

Already collected (often Google Sheets / Score Report), but not normalized or cleaned, no regular path into analytics. Need company-side prep: consistent names, link by ID, keep centrally — to make it usable.

C3

Inside WSDC contour — not collected yet

We believe where to get it inside WSDC. No raw stream yet. First learn to collect → then it becomes C2.

C4

Outside WSDC

Local dances, workshops, non-WSDC weekends, polls. Once collected, those feeds land in C2 (exist, not yet in the shared analytics stream).

C5

Separate circle: scope / governance

Priorities, product, policy, fees — not a dataset. Outside the C1–C4 readiness ladder.

Deep dive · skippable C5 Scope / governance

Not a data readiness question

C3 find / C4 outside → C2 prepare → C1 answer C5 aside

Separate analytics and preparatory data work from strategy, product, and policy — so the committee stays on data readiness and current initiatives (Kay).

What it is

  • Priorities, mandate, mission stretch
  • Website / product features (e.g. rankings on site)
  • Fees, merge/delete, audit policy

Why it stays off the ladder

  • A new table would not settle this
  • Does not move C3 → C2 → C1
  • Needs a Board / ops decision, not a data path

What we do

  • Return to Board / ops with a clear recommendation (committee focus)
  • May advise with C1 evidence — not own the product
  • Park until Board names an owner or a mandate

Examples from this Board draft

  • JC-7 · Coakley — point ranking history on the website → product call
  • JC-4b · Coakley — listing fees → Board / finance
  • JC-6b · Coakley — audit / merge / delete policy → Board / ops
Process Workflow

From ask to track

  1. Intake — asker, text, must-have vs nice-to-have
  2. Decompose — one Board message → several separate questions
  3. Classify — C1–C5 + population (Community / Entry / Scored)
  4. Respond — deliver (C1), partial + preparatory step (C2/C3), collection design (C4), or return on scope (C5)
  5. Track & reclassify when a preparatory step ships
