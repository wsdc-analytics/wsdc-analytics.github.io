одна рамка для приёма

Как раскладываем запросы Board по готовности данных компании (C1–C5), как вопросы двигаются по мере улучшения источников, и что решаем сегодня — принимаем рамку до сверки матрицы.

Scope Зачем классифицировать

Общая рамка усиливает текущую работу

Вопросы Board приходят смешанными. Рамка называет, что нужно каждому запросу, — комитет может опираться на инфраструктуру и текущие инициативы.

Фокус комитета (Kay)

Усиливать текущие инициативы Board и инфраструктуру. Держать этот фокус, пока Board явно не расширит мандат.

Что даёт классификация

  • Дробит одно сообщение на отдельные вопросы
  • Называет слой данных для каждого вопроса
  • Отделяет готовые ответы от подготовительной работы и от решений про мандат
Frame Популяции

Три популяции. Не смешивать

Community

Широкий мир WCS: social и обучение — в основном вне реестра.

Entry

Все зарегистрированные в WSDC J&J. Уже запрошены в списках участников Score Report — для аналитики нужно хранить их централизованно и связывать по ID танцора и ивента.

Scored

Люди с начисленными поинтами / Competitor ID после поинта. Это то, что публичный реестр поддерживает сегодня.

Competitor ID только после поинта — Rules 2026.1B §3.2.2c. Согласовано с analytics brief от 1 сентября.

Model Категории

Как мы раскладываем вопросы Board

Не «хорошая / плохая база», а готовность данных компании (WSDC) к ответу.

C1

Можно отвечать сейчас

Данные уже в рабочем стриме (Points Registry, каталог ивентов). Часть вопросов — полностью; часть — частично (обычно только Scored), если спрашивающего это устраивает.

C2

Данные в контуре WSDC есть — в стрим ещё нельзя

Уже собираются (часто через Google Sheets / Score Report), но не нормализованы, не почищены, нет регулярного пути в аналитику. Нужна доработка: схема, единые названия, связь по ID, централизованное хранение — чтобы сделать пригодными для аналитики.

C3

В контуре WSDC, но пока не собирали

Предполагаем, откуда взять (внутри WSDC). Пока сырого потока нет. Сначала научиться брать → затем это станет C2.

C4

Вне WSDC

Локальные танцы, воркшопы, non-WSDC weekends, опросы. Когда данные начнут собирать — попадают в C2 (есть, но ещё не в общем аналитическом стриме).

C5

Другой круг: scope / governance

Приоритеты, product, политика, fee — не датасет. К лестнице готовности C1–C4 почти не относится.

Logic Трансформация

Как вопросы двигаются по мере готовности данных

C3 · ещё не брали

Есть гипотеза, где в WSDC лежат данные. Проработать: к кому идти, можно ли взять, в каком виде.

C4 · вне WSDC

Community-сбор. Когда поток появится — тоже в C2.

научиться брать / собирать →

C2 · есть, но не в стриме

Короткий перечень: что получить и чему научиться (регулярный путь: получить → почистить → связать; единые названия). После этого вопросы уходят в C1.

→ научиться работать со стримом →

C1 · отвечаем

Полный ответ или частичный (если устраивает). Сюда схлопывается C2 — и то, что пришло в него из C3 или C4.

C5 · отдельно

Стратегия и ownership — не этап этой лестницы.

Развилка C3 / C4 → обе кормят C2. Дальше C2 → C1. Следующие слайды — каждая ступень подробно (на созвоне можно пролистнуть; полезно при чтении после).

Deep dive · можно пролистнуть C1 Можно отвечать сейчас

Рабочий стрим — аналитика уже возможна

C3 найти / C4 вне → C2 доработка → C1 ответ C5 отдельно

Points Registry и каталог ивентов регулярно обновляются. Полный ответ, где вопрос укладывается в Scored; частичный — если спрашивающего устраивает этот слой.

Что есть

  • Поинты / размещения / Competitor ID после поинта
  • Каталог ивентов и scored-ландшафт YOY
  • Готовая C1-работа (напр. переходы дивизионов)

Ограничения

  • Scored ≠ Entry / attendance / «held»
  • Частичный ответ надо явно маркировать — не «вся community»
  • Invitational / no-shows из реестра одними не закрыть

Качество на этом слое

  • Меньше свободного текста; стандартизация сущностей
  • Регулярные таблицы: танцор · ивент · результат
  • Качество WSDC-слоя — не спор «чья база»

Примеры из этого драфта Board

  • JT-1 · Tigges — время в дивизионе → C1 полный (путь через реестр уже есть)
  • JN-1b · Jen — сколько дошли до All-Star → C1 полный
  • YV-1 · Yvonne — competitors по skill level → C1 частичный (только Scored; полный Entry — C2)

После принятия рамки естественные C1-пакеты: прогрессия / структура поинтов · scored-ландшафт ивентов · пути Champions и inactivity (с оговорками).

Deep dive · можно пролистнуть C2 Есть — не в стриме

Уже в контуре WSDC — ещё не стыкуется

C3 найти / C4 вне → C2 доработка → C1 ответ C5 отдельно

В Score Report / Sheets уже есть зачатки (часто с ~2023). Можно проектировать, как они войдут в общий аналитический стрим рядом с C1.

Что уже есть

  • Отчёты ивентов: тиры, counts по номинациям / ролям
  • Competitors List — проблемный, но след есть
  • Тот же контур, что требования к спискам участников Score Report

Ограничения

  • Глубина в основном с ~2023
  • Нет устойчивой схемы; не храним централизованно; не связаны по ID танцора / ивента
  • Пока не садится в общий аналитический стрим рядом с C1

Путь → C1

  • Регулярный путь: получить → почистить → сущности → связать с C1
  • Единые названия ивентов и мест
  • Архив до 2023 / пропуски → часто сначала C3, потом C2

Примеры из этого драфта Board

  • YV-1-E · Yvonne — тот же вопрос про competitors → хранить списки Score Report централизованно и связать по ID
  • PL-1b · Paul — prelims / shelf judges → поля есть в Score Report, ещё не в общем стриме

List участников ещё зачаток: практический добор — scoring-системы. Текущие частичные фиды остаются C2, пока не связаны с C1.

Deep dive · можно пролистнуть C3 В контуре — ещё не брали

Полагаем, что лежит в WSDC — пока не забирали

C3 найти / C4 вне → C2 доработка → C1 ответ C5 отдельно

По вопросам Board: к кому идти внутри WSDC, что запросить, можно ли взять. Часто — архив / обогащение того же блока, что C2.

Типичные пробелы

  • Глубина Score Report / списков до 2023
  • Home city/state, official dates, потоки судей AJP
  • Поля где-то в ops — не в нашем стриме

Работа сейчас

  • Найти владельца и формат внутри WSDC
  • Подтвердить: можно ли получить и на каких правилах
  • Не выдавать за уже готовое к аналитике

Дальше — повышение

  • Нашли и можно брать → C2
  • Регулярный путь + связь с C1 → C1
  • Не нашли / вне контура → пересмотр (C4 / парк)

Примеры из этого драфта Board

  • JC-3b · Coakley — история Classic/Showcase → нет в Points Registry; сначала искать внутри WSDC
  • PL-3 · Paul — реестр сертифицированных судей AJP → дизайн: кто держит и как забрать
Deep dive · можно пролистнуть C4 Вне WSDC

Локальный мир WCS — не контур реестра

C3 найти / C4 вне → C2 доработка → C1 ответ C5 отдельно

Воркшопы, локальные танцы, non-WSDC weekends, популяция WCS вокруг ивентов (напр. JN-3c). Здесь старт — дизайн сбора, не extract из Points Registry.

Что это

  • Community-ландшафт вне ивентов WSDC
  • Радиус от venue / локальная популяция
  • Точность не будет registry-grade

Как организовать

  • Начать с уже собранных community-хабов (примеры ниже), затем закрывать дыры
  • Возможно regional leads из других комитетов
  • Сектора / регионы + cadence проверки; владелец и мандат Board

Дальше

  • Когда поток есть → C2
  • Комитет может советовать структуру — программа и product остаются у Board
  • Product / fee / hub-политика → C5

Примеры из этого драфта Board

  • JC-1 / JC-2 · Coakley — воркшопы и локальные ивенты по миру → community-сбор
  • JN-3c · Jen — WCS-население в 100 милях от ивента → локальная community, не реестр

Примеры уже централизованных community-листингов (не WSDC, не registry-grade): weekenders.dance · westiehub.dance

Deep dive · можно пролистнуть C5 Scope / governance

Это не вопрос готовности данных

C3 найти / C4 вне → C2 доработка → C1 ответ C5 отдельно

Отделить аналитику и подготовительную работу с данными от стратегии, продукта и политики — чтобы комитет оставался на готовности данных и текущих инициативах (Kay).

Что это

  • Приоритеты, мандат, растягивание mission
  • Сайт / product (напр. рейтинги на сайте)
  • Fee, merge/delete, политика аудита

Почему не лестница данных

  • Новая таблица этот вопрос не закроет
  • Не двигается по C3 → C2 → C1
  • Нужно решение Board / ops, а не путь данных

Что делаем

  • Вернуть Board / ops с ясной рекомендацией (фокус комитета)
  • Можно советовать на уже готовых C1-ответах — не владеть продуктом
  • Паркуем, пока Board не назначит владельца или мандат

Примеры из этого драфта Board

  • JC-7 · Coakley — история рейтинга на сайте → product
  • JC-4b · Coakley — listing fees → Board / finance
  • JC-6b · Coakley — политика аудита / merge / delete → Board / ops
Process Процесс

От вопроса к трекингу

  1. Приём — кто спросил, текст, must-have vs nice-to-have
  2. Декомпозиция — одно сообщение Board → несколько отдельных вопросов
  3. Классификация — C1–C5 + популяция (Community / Entry / Scored)
  4. Ответ — отдать (C1), частичный ответ + подготовительный шаг (C2/C3), дизайн сбора (C4) или вернуть по scope (C5)
  5. Трекинг и переклассификация — когда подготовительный шаг сделан
